Gitleaks [maintainers identify it as feature-complete](https://github.com/gitleaks/gitleaks) with security maintenance focus and point to Betterleaks as successor. Gitleaks git mode uses `git log -p`; dir mode uses files. Its default/config discovery, `.gitleaksignore`, `gitleaks:allow`, rules and path exclusions can suppress findings; `--redact` documents log/stdout behavior, not proof every report sink is safe. The separately licensed [Gitleaks GitHub Action](https://github.com/gitleaks/gitleaks-action) requires a license key for organization use; do not equate its terms with MIT CLI.

Betterleaks v1 can scan local files/git and can also access remote services and validate credentials. [v2 migration](https://github.com/betterleaks/betterleaks/blob/main/docs/v2_migration.md) documents that v2 detection defaults differ from opt-in validation/analysis and that remote source retrieval can still use network. [v2.0.0-rc.6](https://github.com/betterleaks/betterleaks/releases/tag/v2.0.0-rc.6) is prerelease, not stable v1; its changed JSON and removed SARIF require a separate adapter decision. Validation, analysis, revoke and remote source commands are prohibited in the proposed pilot. Do not assume v2 settings apply to v1.

OSV [offline documentation](https://github.com/google/osv-scanner/blob/v2.7.0/docs/offline-mode.md) distinguishes `--offline` from `--offline-vulnerabilities`: the latter can permit other network activity, including dependency resolution. Update/download flags, `fix`, registry resolution, license retrieval and image modes are outside the pilot. Offline databases require separately sourced, authenticated ecosystem snapshots and freshness; commit-level offline scanning is limited. [Privacy and endpoints](https://github.com/google/osv-scanner/blob/v2.7.0/README.md) describe potential package/version/hash disclosure. Verify exact version behavior in future inert tests.

Semgrep [metrics](https://github.com/semgrep/semgrep/blob/develop/metrics.md) may depend on registry/login/config; local-only settings and enforced egress denial require later validation. CodeQL CLI [terms](https://github.com/github/codeql-cli-binaries/blob/main/LICENSE.md) also distinguish academic research, open-codebase analysis and paid entitlements; applicability to each target and distribution requires legal/owner assessment. Neither licensing nor absence of network has been tested here.

## Decision matrix

Weights are a **qualitative heuristic**, not a security score; unknown facts are not awarded points. A = one Gitleaks-format synthetic importer, no scanner; B = add OSV synthetic importer; C = several categories immediately. Fixture interpretation is not real scan coverage.

| Criterion / weight | A | B | C |
|---|---|---|---|
| Safe bounded invocation 25% | No invocation; smallest exposure | No invocation in fixture step; two future execution boundaries | Multiple unvalidated boundaries |
| Evidence validity 20% | One native schema and coverage negatives | Adds DB freshness and package identity | Heterogeneous contracts and unknowns |
| Offline/privacy 15% | Inert synthetic data only | Additional future DB/update separation | Multiple telemetry/network surfaces |
| License/distribution 15% | MIT CLI candidate; no binary/rules redistributed | Apache candidate plus DB data terms remain unresolved | CodeQL and Semgrep rule terms unresolved |
| Platform 10% | Fixture parsing portable; release assets named for target OS | Similar asset availability, behavior untested | SAST platform support unresolved |
| Maintenance 10% | Feature-complete Gitleaks means reduced new features | Active OSV DB and scanner change management | Broader update burden |
| Simplicity 5% | Smallest | More work | Highest |

**Recommendation: A**, pending independent review and explicit owner authorization. Use invented non-secret JSON samples based on documented Gitleaks v8.30.1 structure, not copied implementation or real scans; do not assert they are real scanner results. B is a later separate increment after freshness and ecosystem contracts mature; C is deferred. Betterleaks remains a conditional future alternative if its stable schema, output, configuration and passive-only behavior are verified. No numerical winner is manufactured from unknown licensing or isolation facts.

## Other supply-chain formats and rights

[OSV supported formats and usage](https://google.github.io/osv-scanner/usage/) must be pinned per ecosystem; `cargo-audit` targets Cargo, `npm audit` and `pip-audit` have package-manager/service and version-specific behavior requiring separate research, so none is selected. [CycloneDX specifications](https://cyclonedx.org/specification/overview/) and [SLSA provenance verification](https://slsa.dev/spec/v1.2/verifying-artifacts) offer future input/provenance candidates; an SBOM is an inventory, not proof of completeness or authentic provenance. Do not add a graph database.

Reading docs, invoking an independently installed binary, automation, redistribution, rule bundling, hosted service and commercial output use are distinct legal questions. MIT/Apache obligations include preserving relevant notices; LGPL distribution duties and exact rule/data licenses require review. No entitlement to redistribute a scanner, rules or DB is inferred from this document. No legal conclusion, binary installation or scanner execution is claimed.

Alternative SCA choices: [RustSec](https://github.com/RustSec/advisory-db) documents `cargo-audit` for Cargo.lock and an advisory database; this is narrower than polyglot OSV. No alternative is selected or run. Their ecosystem limits and network behavior matter more here than an unverified numerical score.
