# GOV-02 R2 — fixture finding interpretation

AUTHOR CANDIDATE; SYNTHETIC ONLY. R1's `parse_gitleaks_fixture` remains a bounded syntactic parser: `findings.len()` is parsed elements, not confirmed detections. The new `interpret_gitleaks_fixture_v2(bytes, Option<&[&str]>)` uses the same parser and limits. It classifies `[{}]` as one parsed, zero usable, one insufficient. A usable record under this **selected fixture profile** has nonempty RuleID, File and Fingerprint; positive coordinates, end line >= start line, and end column >= start column for a single-line range. These are fixture requirements, not universal upstream guarantees. Missing or unsupported native fields can be legitimate in other producer modes.

The v2 receipt reports parsed, usable, insufficient, fixture catalog matches, unknown rules when a catalog is supplied, duplicate and missing fingerprint claims. Matching is exact against a separate caller-supplied slice and returns only indexes into that slice, never native text. `fixture_catalog_matches` means matched test-catalog entries only: `catalog_is_caller_declared=true` always, even if the caller supplies both data and catalog; it does not prove independent authority, approved policy or rule coverage. With no catalog no approval is asserted. Duplicates are counted only within this import; no identity database or collision-free property is claimed. Fingerprints may contain path, rule and source metadata; raw values never leave the function and no stability, secrecy or cryptographic uniqueness is promised. No filename, URL, rule ID, fingerprint, Match or Secret is emitted. Input-derived strings can remain temporarily in memory; host compromise and secure erasure are unsolved.

`[]`, `null`, missing bytes and malformed bytes retain distinct R1 outcomes. All receipts remain test-only; report authentication, scanner execution, coverage, policy authority and operational PASS are false. A match or usable record is not a scan result. Unknown catalog absence is not evidence of zero unknown upstream rules. R1 and R2 reject duplicate JSON fields, unknown fields, oversized and unsupported nested records.

Source facts: [v8.30.1 native finding](https://github.com/gitleaks/gitleaks/blob/v8.30.1/report/finding.go), [JSON serializer](https://github.com/gitleaks/gitleaks/blob/v8.30.1/report/json.go), [directory mode](https://github.com/gitleaks/gitleaks/blob/v8.30.1/cmd/directory.go), [upstream usage](https://github.com/gitleaks/gitleaks/blob/v8.30.1/README.md). The Go struct itself does not impose this profile. Native fingerprint includes source-dependent components in upstream examples; equality alone does not establish same finding.
