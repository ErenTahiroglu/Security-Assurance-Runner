# GOV-02 EXEC-01 — synthetic signed execution statements

Author candidate; not independent acceptance. `execution_witness::verify_test_execution` takes DSSE-PAE typed plan bytes/signature, independently supplied witness bytes/signature, native report bytes and `TestContext`. The context provides external test verification keys, issuer identities, a pre-established exact plan-byte SHA-256, clock/freshness and revocation assumptions. Neither statement can enroll its own key. Existing Ed25519 `verify_strict`, weak-key rejection, and DSSE encoding from `trust::pae` are reused; no cryptography or dependencies added. Statements are bounded, strict JSON with separate types, roles, purposes and validity windows.

The signed plan binds repository, full commit, run/stage/attempt, tool version, binary/input/config digests, source inventory and rule catalog. Witness binds the same values, exact signed-plan digest, report byte digest/length and start/termination/timeout/error state. Changed binding, wrong issuer, signature, version, time, digest or incomplete execution refuses. Replay across an externally pinned different plan/run is rejected; this is **not persistent replay protection**, and replay of the identical witness under the identical plan remains possible. Caller-supplied fixture roots or clock are not operational authority.

The existing `gitleaks_adapter::assess` consumes the signed statement values; its decision remains `INDETERMINATE`. Native parser bounds and supported-subset limits remain. Scope counts only profile-usable claims with exact safe relative names in the signed synthetic inventory. Absolute, traversal, encoded, backslash and out-of-inventory names do not match; no path is opened, resolved or authenticated. Scope matches are report claims, not independently observed files. Rule identities matched in findings do not prove rules ran; duplicate claims cannot establish other required rules. Actual rule execution and coverage stay unverified. Fingerprints, paths, raw identifiers, secrets and report bytes are not emitted in receipt or errors.

The receipt says two signatures were verified under the **test roots**, while process execution, policy authority and coverage remain false. Neither signature proves a process ran: there is no independently established host/provider observation or production enrollment. Compromised host, key custody, clock/revocation freshness and output origin remain unresolved. No scanner installation, scanner execution, real target, operational PASS/BLOCK or new one-shot workflow occurs.
